# 13. 품질 검사 루프

## 0. 왜 생겼나

외부 평가에서 학습지 세 장이 **22 / 30 / 35점(100점 만점)** 을 받았다.
디자인 점수는 높았다. 평가자의 결론은 이것이다.

> 예뻐서 좋은 학습지처럼 느껴진다. UX 가 매끄러워서 수동적 읽기, 얕은 문제, 개념적 단순화가 잘 보이지 않는다.

지적을 한 줄로 줄이면 — **"학생이 무엇을 읽었는가" 만 있고 "무엇을 했는가" 가 없다.**

그리고 우리 검사는 말투와 스키마만 봤다. **학습이 일어나는지는 보지 않았다.**

## 1. 구조

```
설계 (opus) ─→ 집필 (sonnet) ─→ ┌─ 스키마 검증
                                  ├─ 설계 정합성  (cross-check)
                                  ├─ 말투         (voice-lint)
                                  ├─ 학습설계     (pedagogy-lint)   ← 새로 생김
                                  └─ 검사관       (critic, opus)    ← 새로 생김
                                        │
                              통과 ─────┴───── 반려
                                │                │
                              렌더            재작성 (sonnet, 사유 첨부)
                                                 │
                                          다시 검사 (최대 2회)
                                                 │
                                          그래도 반려 → draft_quality_rejected, 환불
```

두 겹이다. **기계적으로 잡히는 것은 코드가, 판단이 필요한 것은 검사관이.**
검사관에게는 정적 검사가 이미 잡은 목록을 함께 넘겨서 같은 걸 두 번 지적하지 않고 그 너머를 보게 한다.

## 2. 정적 검사 — `pedagogy-lint.ts`

| 규칙 | 실패 조건 | 지적의 출처 |
|---|---|---|
| 읽기만 하는 본론 | 활동이 있는 블록 < 50% | "읽기가 학습의 대부분" |
| 시각자료 없음 | 수학·과학·미술·경제인데 `figures` 가 0개 | "머릿속으로 그려 보세요 는 도형이 아니다" |
| 전이 거리 허위 | `far` 인데 정답 문구가 본문에 그대로 있음 | "문제와 본문의 거리가 너무 가깝다" |
| 본문 복사 확인 | 5문제 중 4개 이상이 본문 베낌 | 같음 |
| 문체 템플릿 | 파르의 말이 전부 "저도/저는…" | "친절함보다 장식적인 문장이 누적" |
| 오개념 | 분야별 금지 헤드라인 (아래) | P0 |
| 미검증 사실 | `confidence != high` 인 역사 | "사실검증 프로세스를 UI 로 대체" |

**분야별 오개념 표** — 평가에서 지적된 문장을 그대로 패턴으로 만들었다.

| 분야 | 잡는 것 | 이유 |
|---|---|---|
| 물리 | "보는 순간 / 지켜보면 / 의식이 바꾼" | 관측 = 시선 오개념. 제목이 먼저 심으면 본문에서 정정해도 늦다 |
| 물리 | "알갱이가 아니다" | "전자 ≠ 입자" 로 저장됨. "고전적 입자 모델로는 설명 못 함" 이어야 |
| 물리 | "탐지기 붙이면 두 무더기" | 이분법. 경로정보가 늘수록 연속적으로 약해진다 |
| 수학 | "도착은 못 해도" | 극한은 도착 여부가 아니라 주변 값의 방향 |
| 수학 | "dx = 아주 작은 변화량" | dx 를 작은 Δx 로 기억하게 됨 |
| 수학 | "시험 문제의 절반" | "왜 그런지 넘어가지 말라" 와 충돌 |
| 미술 | "한 번 날아간 건 되살릴 수 없다" | RAW 는 일부 복구 가능. 기준은 "중요 디테일에서 전 채널 손실" |
| 미술 | "스포이드로 찍으면 한 번에 맞는다" | 화면에서 회색인 것 ≠ 중성 |

**반박 문맥은 잡지 않는다.** "누군가 X 라고 말한다면 어떻게 답하겠어요?" 는 평가자가 권한 문제 형식이다.
오개념 문구 뒤 40자 안에 부정(않·아니·오해·안 돼요…)이 오면 교정 문장으로 본다.
그리고 **필드를 이어붙여 검사하지 않는다** — 앞 필드의 오개념이 뒷 필드의 교정 문장 덕에 숨는 일이 실제로 있었다.

## 3. 검사관 — `critic.ts`

루브릭 8개, 각 0~10점. 75점 미만이거나 `must_fix` 가 하나라도 있으면 반려.

| 항목 | 묻는 것 |
|---|---|
| activity | 설명 한 단위마다 학생이 결정·예측·계산·표시하는가 |
| representation | 과목 표상이 실제로 있고 본문이 그것을 쓰는가 |
| transfer | 문제가 새 상황·반례·오류 분석인가 |
| misconception | 단순화가 잘못된 개념으로 굳지 않는가. 은유와 사실의 경계를 표시하는가 |
| feedback | 오답 진단이 있는가. "본론 N번" 은 해설이 아니다 |
| alignment | 목표·활동·평가가 1:1 인가 |
| honesty | 시간이 분리되어 맞는가. 선수지식을 밝히는가 |
| voice | 파르가 교정·힌트에만 쓰였는가 |

시스템 프롬프트의 핵심 문장:

> 매끄러운 UX 가 수동적 읽기, 얕은 문제, 개념적 단순화를 가립니다. 겉모습에 속지 마세요.
> "입문자를 위해" 라는 이유로 핵심 표상을 제거한 경우, 그건 배려가 아니라 결함입니다.

`must_fix` 의 `fix` 는 구체적이어야 한다 — "더 좋게" 가 아니라 "Q1 을 고전적 입자 모델로는 왜 설명 못 하는지 묻는 문제로 바꾼다".
그 문장이 그대로 재작성 프롬프트가 된다.

## 4. 스키마가 바뀐 것

지적을 받아들이면 스키마에 **활동과 표상이 들어갈 자리** 가 있어야 했다.

| 추가 | 왜 |
|---|---|
| `figures[]` — 구조화 스펙 (`plot` `distribution` `tonecurve` `swatches`) | LLM 이 SVG 를 쓰면 렌더가 깨지고 XSS 가 열린다. 스펙만 받고 `figures.ts` 가 결정론적으로 그린다 |
| `blocks[].activity` — predict / decide / compute / draw / explain | 설명 뒤에 학생이 할 일. 절반 이상 필수. 답(`reveal`)은 접혀 있다 |
| `blocks[].figure` | 그림 참조. 그림에 직접 표시하는 과제(`drawTask`)가 있으면 그림 위에 필기 여백 |
| `quiz[].transfer` near/far | far 2개 이상 필수 |
| `quiz[].misconceptions[]` | "이렇게 답했다면" — 오답 유형별 진단 |
| `time {core, practice, optional}` | "약 26분" 하나는 숙제 40분과 충돌해 아무도 못 믿는다. optional 은 숙제 합계와 같아야 한다(검증기) |
| `assumes[]` | "입문" 이 무엇에 대한 입문인지 |
| `guide_notes` 최대 2 | 파르 과사용 방지 |

**뺀 것**: `estimated_minutes`, "확실하지 않음" 배지 정책.
미검증 사실은 배지를 달아 내보내지 않고 **검증하거나 뺀다**. `uncertainty_note` 는 뉴턴·라이프니츠 우선권처럼
학계에서 실제로 갈리는 문제에만 쓴다.

## 5. 비용이 올랐다 — 솔직하게

검사관은 판단이 필요해서 opus 를 쓴다. 학습지 JSON(~9K) 을 읽고 800 토큰쯤 낸다.

| 경로 | 비용 | 원화(1,400원/USD) |
|---|---|---|
| 초안 통과 (설계 + 집필 + 검사 1회) | $0.172 | **240원** |
| 재작성 1회 | $0.315 | 441원 |
| 재작성 2회 (상한) | $0.458 | 641원 |
| 평균 (재작성률 30% 가정) | ≈ $0.215 | **≈ 300원** |

이전 목표 150원의 두 배다. 유닛 이코노믹스(`10-pricing.md`)에 반영했다.
10장 팩 기준 손익분기 결제 전환율은 **3.1% → 8.6%** (수수료 15%), 30% 수수료면 11.5%.
여전히 성립하지만 여유가 줄었다.

**이 비용을 깎지 않는 이유**: 평가자가 준 점수는 22~35점이었다.
그 학습지를 150원에 만드는 것보다 제대로 된 학습지를 300원에 만드는 쪽이 사업이다.
재작성률이 실측에서 10% 아래로 내려오면 검사관을 sonnet 으로 내리는 것을 검토한다.

## 6. 남은 것 (이번에 안 한 것)

| 항목 | 왜 미뤘나 |
|---|---|
| 11단계 템플릿 폐기 → `문제 제시 → 예측 → 관찰 → 개념 → 연습 → exit ticket` | 11개 섹션은 제품 초기 요구사항이다. 활동·도형을 섹션 안에 넣는 것으로 먼저 대응했고, 템플릿 자체를 바꿀지는 실측 후 결정 |
| 필기 좌표를 요소(문항·활동)에 앵커링 | 응답 모델은 V4 에서 들어갔다(§8). 필기 자체를 요소에 붙이는 건 필기 엔진 재설계와 함께 |
| 반응형 리플로우 + 필기 분리 | 위와 같은 작업. `user-scalable=no` 는 먼저 제거했다 |

## 7. 회귀 방지

- 픽스처 4장이 정적 검사 전부 통과 (`server/tests/selfcheck.ts`)
- 파이프라인 테스트가 검사 루프의 네 경로를 고정: 통과 / 반려→재작성→통과 / 정적 지적→재작성 / 상한 초과→실패+환불
- 오개념 린트는 V3 평가 문장 8건을 잡고, 같은 문장의 반박형 4건은 통과시키는지 테스트
- 상호작용 런타임은 실제 Chromium 에서 검증 (`interact.browser.test.ts`): 고르기 전 답 잠금, 오답별 피드백, 슬라이더가 곡선 위를 달리는지
- 평가에서 받은 문장을 픽스처에 다시 넣으면 빌드가 깨진다

## 8. V3 평가 (48 / 55 / 68) 에 대한 대응

두 번째 외부 평가. 첫 평가(30/22/35)보다 올랐지만 아직 낙제다. 지적을 P0 / P1 / P2 로 받았다.

### P0 — 내용 오류 (전부 고침, 린트로 재발 방지)

| 지적 | 고친 것 | 재발 방지 |
|---|---|---|
| 미분: "정확히 접선이 되려면 h를 0으로 놓는다" | 차분몫 h≠0 의 값들이 h→0 일 때 갖는 극한. 왼쪽 접근(h<0) 표를 추가하고 `|x|` 로 "양쪽이 다르면 미분이 없다" 블록 신설 | `오개념` 린트 (math) |
| 미분: "초등학교 산수" | "익숙한 평균 변화율 계산" | `오개념` 린트 (math) |
| 이중슬릿: "슬릿 하나 = 봉우리 하나" | 단일슬릿 회절(중앙 최대 + 측면 최대) 도형, `idealized` 표시 필수, 문제 하나를 회절로 교체 | 검증기가 `distribution` 에 `idealized: true` 강제, 린트 |
| 이중슬릿: "둘 다 아니다", "질문이 답의 모양을 정한다" | 현상 중심 서술 + \|ψ₁+ψ₂\|² 블록 | 린트 (science) |
| 색보정: "회색 카드는 조명을 덜 받아서" | 피사체와 **같은** 조명을 받아야 그 조명을 잰다 — 본문·예시·활동·문제 네 곳에 | 린트 (art) |
| 색보정: 순서 = 규칙, "따뜻하게 = 노랑+파랑" | 순서는 초보용 진단 scaffold, 룩은 예시 A/B 병렬 | 린트 (art) |

### P1 — 구조 (고친 것)

| 지적 | 고친 것 |
|---|---|
| 설명 전에 예측이 없다 | `what_we_learn.hook` — 1번 섹션 첫 요소. predict/decide 만 허용(검증기). 렌더 테스트가 비유보다 앞에 오는지 고정 |
| 데이터 모델이 static document | 활동·문제마다 `data-response-id`, 선택은 라디오, 서술은 "적었어요" 체크. 고르기 전엔 답이 안 열리고, 고른 오답에 맞는 피드백만 뜬다. 응답은 `ONPAR_RESPONSES` + Flutter 브리지(`learn`) |
| 빈 필기 칸 15개 | 과제가 붙지 않은 여백은 전부 뺐다. 렌더 테스트가 "모든 ink-space 앞 500자 안에 프롬프트" 를 강제 |
| 슬라이더가 없다 | `interactive: true` 도형. 할선 h 슬라이더(h<0 포함, h=0 은 ±0.01 로 비껴감), 경로정보 슬라이더(연속) |
| 보조 콘텐츠가 핵심 경로를 묻는다 | 섹션에 `core` 플래그. 탄생 배경·상황극·꿀팁·사전학습·다음 단계는 접힌 채(`<details>`) 시작. `corePathRatio` 지표 |
| 마무리에 성찰이 없다 | `wrap_up.reflection` — 처음 예측(hook)으로 돌아가는 한 줄 쓰기 + 필기 칸 |

### P2 — 하지 않은 것과 이유

| 지적 | 상태 |
|---|---|
| **11개 섹션 구조 해체** ("가장 큰 개선") | 제품 초기 요구사항이라 임의로 못 바꾼다. 이번엔 `core` 플래그로 핵심 경로(1·6·8·9·10)를 앞세우고 나머지를 접었다. 해체 여부는 **사용자 결정 사항**으로 올린다 |
| 색보정에 실제 사진 | 텍스트 생성 파이프라인이 사진을 못 만든다. 별도 자산 파이프라인(라이선스 있는 샘플 RAW + 서버 렌더) 필요. 미착수 |
| 반응형 리플로우 + 요소 앵커 필기 | 필기 엔진 재설계와 함께 (§6) |

### 남은 리스크

- 픽스처 4장은 손으로 고쳤다. **모델이 만드는 학습지** 가 같은 수준인지는 실호출 후에만 안다. 린트·검사관이 방어선이지 보증이 아니다.
- 오개념 린트는 정규식이다. 같은 오개념을 다른 문장으로 쓰면 못 잡는다. 검사관(opus)이 두 번째 방어선.
