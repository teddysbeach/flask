# 17. 출시와 운영

만든 것을 내보내고, 내보낸 뒤에 지키는 일을 적는다.
`15-robustness.md` 가 "무엇이 튼튼함인가" 라면 이 문서는 **"언제 내보내고, 깨졌을 때 무엇을 하는가"** 다.

---

## 1. 출시 게이트

아래가 전부 초록이 아니면 스토어에 올리지 않는다. 하나라도 빨강이면 **날짜를 미룬다.**

| # | 게이트 | 확인 방법 | 지금 |
|---|---|---|---|
| 1 | 서버 테스트 전부 통과 | `bash server/tests/run.sh` | ✅ |
| 2 | 앱 정적 분석 무경고 | `flutter analyze` | ✅ |
| 3 | 앱 테스트 전부 통과 | `flutter test` | ✅ |
| 4 | 12개 카테고리 픽스처가 검사 루프를 통과 | `node --experimental-strip-types server/tests/selfcheck.ts` | ✅ 12/12 |
| 5 | **실물 자극이 필요한 카테고리에 자산이 있다** | `pedagogyLint.releaseBlockers` 가 빔 | ❌ 색보정 사진 미확보 |
| 6 | 실기기 Apple Pencil 필압이 WKWebView 안에서 살아있다 | iPad 실기기 수기 확인 | ❌ 미검증 |
| 7 | 결제 영수증 검증이 샌드박스에서 왕복 | Apple 샌드박스 · Play 라이선스 테스터 | ❌ 스토어 계정 필요 |
| 8 | 계정 삭제가 실제로 지운다 | `delete-account` 후 재로그인 불가 확인 | ✅ 코드 · ❌ 실환경 |

5·6·7 은 **코드로 풀 수 없는 항목**이다. 자산 구매·실기기·스토어 계정이라는 외부 의존이 있고,
그래서 "코드가 다 됐으니 출시 가능" 이라고 말하지 않는다. 게이트는 게이트다.

### 로버스트니스 예산
`15-robustness.md` 의 예산을 출시 시점에 한 번 정산한다.
새 기능이 예산을 넘기면 **기능을 빼지, 예산을 늘리지 않는다.**

## 2. 스토어 등록

### 2-1. 공통

| 항목 | 값 |
|---|---|
| 번들 ID / applicationId | `me.popol.onpar` |
| 표시 이름 | 온파 |
| 카테고리 | 교육 |
| 연령 등급 | 전체이용가 (4+) — UGC·외부 링크·광고 없음 |
| 지원 언어 | 한국어 |
| 지원 URL / 개인정보 URL | `onpar.app/support` / `onpar.app/privacy` |

버전은 `1.0.0`, 빌드 번호는 **단조 증가 정수**. 강제 업데이트 판정(`AppGate`)이 빌드 번호를 정수로 비교하므로
빌드 번호를 되돌리거나 플랫폼마다 다르게 매기면 게이트가 오작동한다.

### 2-2. 인앱 상품 (소모성 3종)

| 상품 ID | 이름 | 가격 | 지급 |
|---|---|---|---|
| `onpar.sheets.3` | 학습지 3장 | 4,900원 | 3 |
| `onpar.sheets.10` | 학습지 10장 | 12,900원 | 10 |
| `onpar.sheets.30` | 학습지 30장 | 29,900원 | 30 |

스토어의 상품 ID·지급량은 **DB `products` 테이블과 반드시 일치**해야 한다.
지급량의 진실은 서버에 있다(`verify-purchase` 는 앱이 보낸 장수를 절대 믿지 않는다).
스토어에만 상품을 추가하고 `products` 에 넣지 않으면 결제는 되고 지급은 실패한다 — 반드시 마이그레이션이 먼저다.

### 2-3. 개인정보 라벨 (App Privacy / Data Safety)

없는 것을 없다고 적는 것이 가장 중요한 항목이다.

| 항목 | 수집 | 연결됨 | 추적 | 목적 |
|---|---|---|---|---|
| 이메일 | ✅ | ✅ | ❌ | 계정 식별, 로그인 |
| 사용자 콘텐츠 (학습지 주제·필기·답안) | ✅ | ✅ | ❌ | 서비스 제공 |
| 구매 내역 | ✅ | ✅ | ❌ | 장수 지급, 환불 대응 |
| 사용 데이터 (화면 이동·기능 사용) | ✅ | ❌ | ❌ | 제품 개선 |
| 진단 (크래시) | ✅ | ❌ | ❌ | 안정성 |
| 위치 · 연락처 · 광고 식별자 · 마이크 | ❌ | — | — | **수집하지 않는다** |

- **추적(App Tracking Transparency) 없음.** 광고 SDK도, 제3자 데이터 브로커 전송도 없으므로 ATT 프롬프트를 띄우지 않는다.
- 분석 이벤트는 `sanitizeProps` 로 차단 키를 거르고, 로그는 `AppLogger.redact` 로 이메일·전화·토큰을 지운다.
  라벨에 "사용 데이터 · 연결되지 않음" 이라고 쓸 수 있는 근거가 그 두 함수다.

### 2-4. 스크린샷

6장. **기능 나열이 아니라 한 문장의 이야기**로 배열한다.

1. 배우고 싶은 것을 한 줄 적는다
2. 파르가 학습지를 만든다 (문제 제시 → 예측)
3. 아이패드에 직접 손으로 푼다
4. 예측이 맞았는지 관찰로 확인한다
5. 잊을 때쯤 다시 물어본다 (복습 알림)
6. 필요한 만큼만 산다 (장수 결제)

캡션에 "AI" 를 앞세우지 않는다. 사용자가 사는 것은 모델이 아니라 **손으로 푸는 한 장**이다.

## 3. 심사 대응

### 3-1. 심사 노트에 반드시 적을 것

```
테스트 계정: review@onpar.app / (별도 전달)
이 계정에는 학습지 5장이 미리 지급되어 있어 결제 없이 전체 흐름을 확인할 수 있습니다.

1) 학습지 생성: 홈 → 만들기 → "미분의 의미" 입력 → 40~120초 소요
2) 필기: 생성된 학습지에서 Apple Pencil 또는 손가락으로 필기 가능
3) 복습 알림: 설정 → 알림에서 즉시 테스트 발송 가능
4) 계정 삭제: 설정 → 계정 → 회원 탈퇴 (즉시 삭제되며 복구되지 않습니다)
5) 인앱결제: 홈 → 장수 부족 시 결제 화면. 소모성 상품이며 구독이 아닙니다.

학습지 본문은 서버에서 생성되며 사용자 간 공유 기능이 없습니다(본인만 열람).
```

### 3-2. 예상 지적과 답

| 지적 | 대비 |
|---|---|
| **5.1.1(v) 계정 삭제** | 앱 안에 삭제 경로가 있다(설정 → 계정 → 탈퇴). 문의 메일 유도가 아니라 실제 삭제다 |
| **3.1.1 인앱결제 우회** | 외부 결제 링크가 없다. 가격·구매 안내가 앱 밖으로 나가지 않는다 |
| **4.7 / 4.2 최소 기능** | 필기·복습 스케줄·결제까지 앱 고유 기능이 있다. 웹뷰는 학습지 본문 렌더링에만 쓰고 외부 URL을 열지 않는다 |
| **생성형 콘텐츠 (1.2 / 4.7)** | 사용자 간 콘텐츠 공유가 없어 신고 기능 요건이 적용되지 않는다. 다만 **부적절 주제 입력은 서버에서 거른다**(생성 거부 + 장수 미차감) |
| **권한 사유 문자열** | 카메라·사진만 요청하며 Info.plist 에 한국어 사유가 있다. 쓰지 않는 권한은 선언조차 하지 않는다 |
| **Play 데이터 안전** | 위 2-3 표와 동일하게 채운다. 전송 구간 암호화 ✅, 삭제 요청 경로 ✅ |

**리젝은 사고가 아니라 일정이다.** 첫 제출은 여유를 2주 잡는다.

## 4. 개인정보 처리 매핑

| 수집 | 위치 | 보관 | 탈퇴 시 |
|---|---|---|---|
| 이메일 · 인증 정보 | `auth.users` | 계정 유지 동안 | **삭제** |
| 프로필(닉네임·복습 시각) | `profiles` | 계정 유지 동안 | 삭제(cascade) |
| 학습지 본문·필기·답안 | `worksheets` / Storage / `responses` | 계정 유지 동안 | 삭제 + 스토리지 객체 제거 |
| 구매 내역 | `purchases` | **5년** (전자상거래법) | **익명화**(`user_id → null`, `anonymized_at` 기록) |
| 탈퇴 사유 | `withdrawal_reasons` | 집계 목적 | 애초에 user_id 를 저장하지 않는다 |

구매 내역만 남기는 이유는 법정 보존 의무 때문이고, 그래서 **삭제가 아니라 익명화**다.
이 구분을 개인정보 처리방침에 그대로 적는다. "전부 삭제됩니다" 라고 쓰면 거짓말이 된다.

## 5. 릴리스 절차

1. `main` 에서 태그를 끊는다 (`v1.0.0+1`)
2. CI 3잡 통과 확인 (server / app / drift)
3. **마이그레이션을 먼저 배포**한다. 앱보다 서버가 항상 앞선다
4. Edge Function 배포 → 이전 버전 앱이 여전히 동작하는지 확인(스키마는 더하기만, 빼기는 다음 릴리스)
5. TestFlight / Play 내부 테스트 → 최소 24시간
6. 단계적 출시: **10% → 50% → 100%**, 각 단계 사이 최소 24시간
7. 각 단계에서 크래시율과 생성 실패율을 본다(§7)

### 되돌리기

| 상황 | 되돌리는 방법 | 걸리는 시간 |
|---|---|---|
| 앱 버그 | 단계적 출시 중단 → `app_config.maintenance` 또는 `min_build` 로 게이트 | **분** |
| Edge Function 버그 | 이전 버전 재배포 | 분 |
| 마이그레이션 버그 | 보상 마이그레이션(되돌리는 새 마이그레이션) | 시간 |
| 프롬프트 품질 저하 | `app_config` 없이 함수 재배포 | 분 |

**앱 스토어 롤백은 존재하지 않는다.** 그래서 원격 게이트(`AppGate`)가 있다.
스토어 심사가 며칠 걸리는 동안 사용자를 막을 수 있는 유일한 수단이다.
그리고 게이트 서버를 못 부르면 **통과**시킨다 — 우리 실수로 앱을 잠그는 쪽이 더 나쁘다.

## 6. 사고 런북

| 사고 | 징후 | 첫 조치 | 사용자 |
|---|---|---|---|
| 생성 실패율 급증 | `worksheets.status='failed'` 비율 > 10% | 모델 상태 확인 → 검사 루프 재시도 상한 임시 하향 | **장수 즉시 환급**(이미 코드에 있음) + 안내 |
| 결제 검증 실패 | `verify-purchase` 5xx | Apple/Play 상태 확인. 영수증은 사라지지 않는다 | 앱 재실행 시 자동 재검증. 중복 지급은 `already_processed` 로 막힌다 |
| 장수 오차 신고 | 문의 접수 | `purchases` ↔ `quota_ledger` 대사 | 확인되면 수동 지급 |
| API 키 유출 의심 | 비정상 사용량 | **키 회전 먼저, 조사는 그다음** | 영향 없음(키는 앱에 없다) |
| 알림 폭주 | 같은 항목 반복 발송 | 스케줄 테이블 확인 → 발송 중지 | 설정에서 알림 끄기 안내 |
| 필기 유실 신고 | 문의 | 스토리지 백업 버전 확인 | 복구 가능하면 복구, **불가능하면 솔직히 말한다** |

**필기 유실은 환불로 갚아지지 않는다.** 그래서 저장은 **파일 먼저, DB 나중**이고(반대로 하면 "저장됨" 이라고 적힌 행만 남는다),
다른 기기와 부딪히면 지우지 않고 **합친다**(획 id 합집합). 합치지 못하면 물어보지, 조용히 버리지 않는다.
다만 **앱이 죽은 뒤의 오프라인 필기는 아직 못 지킨다** — 로컬 스풀이 없다. 이건 알고 있는 구멍이고, 다음 릴리스의 첫 항목이다.

## 7. 출시 후 보는 것

숫자를 다 보지 않는다. 아래 다섯 개만 본다.

| 지표 | 임계 | 무엇을 뜻하는가 |
|---|---|---|
| 생성 성공률 | < 95% → 조사 | 제품이 약속을 못 지키고 있다 |
| 생성 소요 시간 p95 | > 150초 → 조사 | 기다림이 이탈이 된다 |
| 학습지당 원가 | > 350원 → 조사 | 가격 설계가 무너진다 (`10-pricing.md`) |
| 복습 알림 열람률 | < 20% → 재설계 | 망각곡선이 작동하지 않는다 |
| 크래시 없는 세션 | < 99.5% → 출시 중단 | 나머지 지표를 볼 자격이 없다 |

전환율과 매출은 **위 다섯 개가 안정된 뒤에** 본다.
망가진 제품의 전환율을 최적화하는 것만큼 헛된 일이 없다.

### 비용 가드레일

- 계정당 일일 생성 상한을 둔다. 장수 결제라 구조적으로는 이미 막히지만, **버그로 장수가 무한히 늘어나는 경우**를 막는 두 번째 벽이다.
- 검사 루프 재시도는 최대 2회. 무한 루프는 원가를 무한대로 만든다.
- 하루 총 생성량이 평소의 5배를 넘으면 알림을 받는다. 성공일 수도 있고 사고일 수도 있는데, **둘 다 즉시 알아야 한다.**
