# 00. 제품 개요 — Baewoom (배움)

> 코드네임 **Baewoom**. 정식 명칭 미정 → `09-open-questions.md` Q1 참조.

## 1. 한 줄 정의

> **배우고 싶은 개념을 입력하면, 서버가 11개 섹션으로 구조화된 학습지(HTML)를 만들어주고,
> 아이패드에서 애플펜슬로 바로 필기하며 풀고, 망각곡선 주기에 맞춰 복습 문제를 로컬 알림으로 보내주는 앱.**

## 2. 왜 만드는가 (문제 정의)

| 기존 학습 방식 | 문제 |
|---|---|
| 검색 / 블로그 | 파편적. "왜 이게 생겼는지"가 빠져 있어 맥락 없이 암기하게 됨 |
| 강의 / 영상 | 수동적. 손으로 쓰지 않아 남지 않음 |
| LLM 챗봇 | 대화가 휘발됨. 다시 안 봄. 구조가 없음 |
| 종이 학습지 | 구조는 좋으나 내가 원하는 주제가 없음 |

Baewoom은 이 넷의 교집합을 노린다: **개인화된 주제 + 고정된 좋은 구조 + 손필기 + 강제 복습.**

## 3. 핵심 가설

1. **구조가 콘텐츠보다 중요하다.** LLM에 "설명해줘"라고 하면 매번 다른 모양이 나온다.
   11개 섹션을 고정하면 사용자는 "다음에 뭐가 나올지" 예측하며 읽을 수 있고, 이게 학습 효율을 올린다.
2. **손으로 쓴 것만 남는다.** 읽기 전용 문서는 소비되고 끝난다. 필기 레이어가 있으면 학습지가 "내 것"이 된다.
3. **복습이 없으면 다 잊는다.** 에빙하우스 망각곡선 기반 간격 반복 알림이 앱의 리텐션 엔진이자 학습 효과의 핵심이다.
4. **처음 2개가 전부다.** 무료 2장의 품질이 곧 전환율이다. 여기서 모델·프롬프트에 아끼지 않는다.

## 4. 스코프

### v1 (MVP)에 들어가는 것

- 이메일 / Apple / Google 회원가입·로그인
- 계정당 **학습지 2개 무료 생성** (원자적 쿼터 차감, 실패 시 자동 환불)
- 주제 입력 → 서버에서 학습지 생성 (11섹션 고정 구조, 비동기 잡)
- 정해진 규격의 HTML 학습지 렌더링 (앱 디자인 시스템과 동일한 토큰 사용)
- 아이패드 필기 레이어 (Apple Pencil 필압/기울기, 팜 리젝션, 펜/형광펜/지우개/실행취소)
- 필기 데이터 로컬 저장 + 서버 동기화
- 망각곡선 복습 스케줄 + **로컬 알림**으로 복습 문제 1개씩 전송
- 복습 카드 화면 (문제 → 정답 확인 → 체감 난이도 → 다음 간격 재계산)
- 사전학습 제안 3개 → 탭하면 해당 주제로 새 학습지 생성 플로우 진입

### v1에 들어가지 않는 것 (명시적 제외)

- 결제 / 인앱구매 (2장 소진 후 "곧 제공" 화면)
- 학습지 공유 / 공개 갤러리 / 소셜
- 웹 버전 (Flutter Web은 v2)
- 필기 OCR, 자동 채점
- 다국어 (v1은 한국어 콘텐츠 전용)
- 푸시(원격) 알림 — v1은 **로컬 알림만**

## 5. 타깃 & 플랫폼 우선순위

1. **iPadOS** (1순위 — 필기가 핵심 가치, Apple Pencil)
2. iOS (iPhone — 조회 + 복습 알림 소비)
3. Android (v1.1)

## 6. 성공 지표 (MVP)

| 지표 | 목표 |
|---|---|
| 학습지 생성 성공률 | ≥ 98% (재시도 포함) |
| 생성 소요 시간 (p50 / p95) | 40s / 120s |
| 가입 → 첫 학습지 완성 전환율 | ≥ 60% |
| 첫 학습지 사용자 중 필기 흔적 남긴 비율 | ≥ 40% |
| D+7 복습 알림 응답률 | ≥ 25% |
