# 14. 실물 자극 (사진 자산)

> 도식으로 대신할 수 없는 학습이 있다. 그걸 코드로 인정한 문서다.

## 1. 왜 필요한가

세 번째 외부 평가가 색보정 학습지에 준 판정은 **74/100, 아직 보류**였고, 이유는 하나였다.

> 회색 카드 색상 견본과 텍스트 비교표는 **개념을 증명하는 자료**입니다.
> 색보정 능력을 훈련하는 자료는 아닙니다.
> SVG 직사각형 세 개에서 warm cast 를 구별하는 학생이 실제 얼굴 사진에서
> WB 문제인지, HSL 문제인지, exposure 문제인지 판단할 수 있다는 보장은 전혀 없습니다.

현재 색보정 학습지가 재는 것: **"화이트밸런스의 정의를 이해했는가?"**
실제 목표여야 하는 것: **"처음 보는 사진에서 원인을 진단하고 적절한 조정을 선택할 수 있는가?"**

둘은 다른 능력이다. 색보정 학습지는 결국 **눈 시험**이어야 하는데 지금은 **이론 시험**이다.

## 2. 구조

```
server/assets/manifest.json      ← 사람이 관리한다. 라이선스·출처·용도.
server/assets/img/               ← 실제 파일
        │
        │  node server/build-assets.mjs
        ▼
server/supabase/functions/_shared/assets.g.ts   ← id 목록 + data URI (생성물)
        │
        ├─ validate.ts   등록되지 않은 assetId 는 거부
        └─ figures.ts    <img src="data:…"> + 저작자 표기
```

학습지 HTML 은 **외부 요청 0회**가 규약이다. 그래서 이미지도 data URI 로 박는다.
`--check` 플래그가 매니페스트와 생성물의 드리프트를 잡는다(다른 생성물과 같은 규약).

### 매니페스트 항목

```jsonc
{ "id": "wb-tungsten-portrait",       // 학습지가 참조하는 이름
  "file": "wb-tungsten-portrait.jpg", // server/assets/img/ 아래
  "credit": "촬영: 홍길동",            // 학습지 그림 아래에 그대로 나간다
  "license": "CC0-1.0",               // 라이선스 식별자
  "source": "https://…",              // 원본 URL 또는 촬영 경위
  "note": "백열등 아래 인물 — 전역 WB 캐스트 판단용" }
```

빌드가 다섯 필드를 전부 요구한다. **출처·라이선스 없는 이미지는 빌드가 거부한다.**
한 장 상한 900KB(넘으면 빌드 실패). 지원 형식 jpg / png / webp.

## 3. 출고 게이트

`pedagogy-lint.ts` 가 `category === 'art'` 인데 `photo` 도형이 하나도 없으면
`releaseBlockers` 에 **`실물 자극 없음`** 을 단다.

`releaseBlockers` 는 `errors` 와 다르다. 의도적으로 분리했다.

| | `errors` | `releaseBlockers` |
|---|---|---|
| 누가 고칠 수 있나 | 모델이 다시 쓰면 고쳐진다 | 사람이 자산을 넣어야 풀린다 |
| 생성 파이프라인 | 재작성 루프에 들어간다 | 들어가지 않는다 |
| 실패 시 | 2회 재작성 후 `draft_quality_rejected` + 환불 | 생성은 정상 완료, 출고만 막힌다 |

모델에게 "없는 사진을 넣어라" 고 두 번 시키고 환불하는 것은 돈과 시간을 버리는 짓이다.
그래서 블로커는 루프 밖에 있다.

## 4. 필요한 자극 세트 (색보정 기준)

평가가 요구한 최소 세트다. 첫 번째는 **설명 전에** 보여줘야 한다.

| 사례 | 학생이 판단해야 할 것 |
|---|---|
| 백열등 아래 인물 | 전역 WB 캐스트 |
| 창빛 + 실내등 혼합 | WB 하나로 해결 안 되는 혼합광 |
| 햇빛 반사 금속 | specular clipping 은 반드시 복구해야 하는가 |
| 하늘 구름 | 중요한 하이라이트 디테일 클리핑 |
| 검증된 그레이카드 포함 사진 | 중성 기준물 선택 |
| 의도적으로 따뜻한 골든아워 사진 | correction 과 creative intent 구분 |

같은 인물·같은 장면을 두 조명에서 찍은 쌍(`compareAssetId`)이 특히 중요하다.
"같은 사람인데 왜 달라 보이는가" 가 이 학습지의 문제 제시이기 때문이다.

## 5. 지금 상태와 다음 결정

**매니페스트는 비어 있다.** 그래서 색보정 학습지는 출고 게이트에 걸려 있다 — 의도한 상태다.
"사진 없이 색을 보는 능력을 가르칠 수 없다" 는 지적을 코드로 옮긴 것이고,
게이트가 없으면 다음 버전에서 이 문제가 조용히 잊힌다.

푸는 방법은 셋이고, **어느 쪽이든 사람의 결정**이다.

1. **직접 촬영** — 가장 확실하다. 라이선스·모델 동의·조명 조건을 통제할 수 있다. 위 6종이면 반나절.
2. **CC0 / CC-BY 사진 사용** — 위키미디어 커먼즈 등. 같은 인물을 두 조명에서 찍은 쌍을 찾기가 어렵고,
   라이선스 표기를 학습지마다 정확히 실어야 한다(`credit` 필드가 그 자리다).
3. **학습자 자신의 사진** — 지금 색보정 학습지가 택한 임시 대응이다. 확장 과제에서
   "같은 사람을 백열등 아래와 창가에서 한 장씩 찍고 같은 보정을 적용해 보라" 로 시킨다.
   실물 자극이긴 하지만 **학습지 안에서 진단을 연습시키지는 못한다.** 게이트는 그대로 걸려 있다.

art 외에도 실물 자극이 필요한 분야가 나올 수 있다(음악의 실제 음원, 요리의 조리 단계 사진).
그때는 `NEEDS_REAL_STIMULUS` 집합에 분야를 추가하고 같은 파이프라인을 쓴다.
