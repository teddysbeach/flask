# 15. 로버스트니스 — 제품 원칙

> 세 번째 외부 평가 이후 이것이 ONPAR 의 최상위 제품 원칙이다.
> 디자인 시스템은 동결한다. 여백·카드·아이콘·문구 톤을 더 다듬는 작업의 ROI 는 거의 0이다.

## 0. 정의

로버스트니스는 "오류가 적다" 가 아니다.

> **학생, 기기, 선행지식, 오답 패턴, 표현 방식, 과목 특성이 달라져도
> 학습목표와 데이터 해석이 무너지지 않는 것.**

"정상적인 학생이 정상적인 화면에서 정상적인 순서로 풀었을 때 잘 된다" 가 아니라,
**예상 밖의 조건에서도 학습이 망가지지 않는 설계**를 말한다.

## 1. 왜 지금 이것이 최상위인가

세 번째 평가의 요지는 칭찬이 아니라 경고였다.

> V5 의 위험성은 오히려 이전보다 미묘합니다. **UI 와 교수설계가 좋아졌기 때문에,
> 남아 있는 단순화·오류·측정 결함이 훨씬 더 권위 있게 보입니다.**

V1 은 학습지처럼 보이는 읽기자료였고, V3 은 학습활동을 붙인 프로토타입이었고,
V5 는 실제 학습 사이클과 상호작용을 가진 교육제품이 됐다.
그래서 이제 실패 모드가 바뀌었다. **못 만든 것이 아니라 너무 그럴듯한 것**이 위험하다.

학생은 예쁘고 정돈된 화면에서 나온 단순화를 사실로 믿는다.
`간섭 가시도 63%` 라고 움직이는 숫자를 보면, 본문에 "대략적 모형입니다" 라고 써 있어도
그 숫자를 법칙으로 기억한다. 텍스트 오류보다 위험하다.

## 2. 세 개의 레이어

로버스트니스는 하나가 아니다. **따로 관리한다.**

| 레이어 | 무엇을 지키는가 | 어디서 강제하는가 |
|---|---|---|
| **콘텐츠** | 단순화가 절대법칙으로 굳지 않는 것 | `boundary`, `model_note`, 오개념 린트, 검사관 `robustness` 루브릭 |
| **평가** | 정답 하나로 "학습했다" 고 판단하지 않는 것 | `evidence`, 증거 종류 3종 이상, `responses` 응답 이력 |
| **런타임** | 기기·JS·입력수단이 달라도 학습이 남는 것 | 요소 기준 필기 좌표, 반응형, textarea+필기 병행, progressive enhancement |

## 3. 콘텐츠 로버스트니스 — 한 문장만 떼어 읽어도 오개념이 생기지 않게

입문자료는 필연적으로 단순화한다. 문제는 단순화가 **절대법칙처럼 보일 때**다.
그래서 모든 핵심 설명은 3단이다.

> **핵심 규칙 → 적용 조건 → 깨지는 경우**

이것이 스키마의 `Boundary { holds_when, breaks_when }` 이고, 최소 한 블록에 필수다(검증기).

| 분야 | 규칙 | 적용 조건 | 깨지는 경우 |
|---|---|---|---|
| 미분 | 두 점을 가까이 하면 할선의 기울기가 접선의 기울기로 간다 | 그 점에서 도함수가 존재할 때 | \|x\| 의 x=0 처럼 양쪽 기울기가 다르면 |
| 이벤트 소싱 | 현재 상태는 이벤트를 replay 해서 만들 수 있다 | 이벤트 스트림이 source of truth 라는 뜻 | projection·snapshot 같은 파생 상태는 실제로 저장한다 |
| 색보정 | 중성 기준물로 WB 를 잡으면 조명 캐스트를 보정할 수 있다 | 기준물과 피사체가 같은 조명을 받을 때 | 혼합광에서는 전역 WB 하나로 해결되지 않는다 |
| 이중슬릿 | 경로 구별 가능성이 커지면 간섭이 약해진다 | 정성 모형이다 | `정보 40% → 간섭 60%` 같은 보편 선형법칙은 없다 |

그리고 **모든 이상화 표상은 자기가 무엇을 생략했는지 말한다**(`figure.model_note`, 검증기가 강제).
단순화는 죄가 아니다. 단순화를 현실의 법칙처럼 숨기는 것이 문제다.

## 4. 평가 로버스트니스 — 정답 하나로 판단하지 않는다

학생은 객관식 정답을 이해해서 맞힐 수도, 찍어서 맞힐 수도, 힌트를 보고 맞힐 수도,
처음 틀리고 고쳐서 맞힐 수도 있다. 전부 `correct = true` 로 뭉개면 학습 데이터가 아니다.

**개수가 아니라 증거 종류로 센다.** `EvidenceKind`:

| 증거 | 무엇을 재는가 |
|---|---|
| `recall` | 정의·용어를 되살린다 (가장 약한 증거) |
| `apply` | 배운 절차를 새 숫자에 적용한다 |
| `compute` | 직접 계산한다 |
| `graph` | 식 없이 그림에서 판단한다 |
| `table` | 수치 표에서 추정한다 |
| `diagnose` | 결과를 보고 원인 후보를 좁힌다 |
| `edge_case` | 규칙이 깨지는 경우를 식별한다 |
| `explain` | 말로 설명한다 |

검증기 규칙: 문항 **4~7개**(5개 고정은 없앴다), 서로 다른 증거 **3종 이상**,
`recall`/`apply` 만으로는 불가, far transfer 2개 이상.

> 미분을 이해했다고 판단하려면 수식 계산 · 그래프에서 기울기 판단 · 표에서 변화율 추정 ·
> 미분불가능한 점 식별 중 셋 이상을 통과해야 한다. 다항식 규칙에 성공하는 것만으로는 부족하다.

응답도 최종 상태가 아니라 **과정**을 남긴다 (`responses` 테이블, 03-data-model.md):
`firstChoice → attempts[] → feedbackSeen → finalChoice`.
첫 오답을 고르고 정답으로 고쳤을 때 **처음 가지고 있던 오개념이 사라지면 안 된다.**
학습분석에서 중요한 것은 정답 자체가 아니라 변화다.

## 5. 표현 로버스트니스 — 한 표상에 학습을 걸지 않는다

하나의 개념을 최소 3가지 방식으로 표현한다. 한 표현에서 막혀도 다른 표현으로 복구할 수 있어야 한다.

| 분야 | 표상들 |
|---|---|
| 미분 | 이야기(순간속도) · 표(h 와 평균변화율) · 그래프(할선→접선) · 수식(차분몫) |
| 이중슬릿 | 점 분포 · 파동/확률진폭 · 간단한 식 · 장치 조건 변화 |
| 이벤트 소싱 | 장부 비유 · 이벤트 스트림 표 · 코드 · 실패 시나리오 |
| 색보정 | 실제 사진 · 히스토그램 · 수치 컨트롤 · 말로 하는 진단 |

## 6. 실패 로버스트니스 — 틀리는 것이 정상 경로다

6단계 구조(문제 → 예측 → 관찰)가 이미 이 방향이다. 더 밀어붙이는 장치가 **로버스트니스 예산**이다.

만들기 **전에** 이 학습지가 막아야 할 오해 3~5개를 적는다 (`robustness.guards`).
각각 어느 단계에서(`where`) 어떻게(`how`) 막는지 밝히고, 린트가 그 섹션이 실제로 막는지 확인한다.

```jsonc
{ "misconception": "평균 속도와 순간 속도가 같다고 생각해요",
  "where": "predict",
  "how": "예측 선택지에 평균 속도 답을 넣고, 관찰 표에서 두 값이 갈리는 것을 보게 해요" }
```

> 좋은 학습지는 **많은 내용을 담은 것**이 아니라 **예상 가능한 실패를 얼마나 잘 막는가**로 평가한다.

예시 — 미분의 예산: ①평균=순간 혼동 ②h=0 직접 대입 ③오른쪽에서만 접근
④도함수=power rule ⑤모든 점에서 도함수 존재. 학습지 전체가 이 다섯에 의도적으로 버텨야 한다.

## 7. 환경 로버스트니스 — 콘텐츠가 주체, 필기가 따라간다

**Progressive enhancement.** JS 가 죽어도 본문·문제·선택지·해설·핵심 그림은 남는다.
JS 가 살아 있으면 슬라이더·즉시 피드백·응답 기록·필기가 붙는다.
연결되지 않은 슬라이더는 CSS 가 감춘다(`figure[data-interactive]:not([data-wired]) .fig__ctl`).

**입력 수단은 최소 둘.** 필기 전용은 스타일러스 없는 기기·접근성에서 학습을 막는다.
서술형 응답 자리마다 `textarea` 와 필기 칸이 나란히 있다.

**필기 좌표는 요소 기준.** 예전에는 820px 문서 절대좌표였고, 그래서 리플로우를 금지해야 했다.
390px 폰에서 문서를 통째로 맞추면 스케일 0.48 — 18px 본문이 8.6px 로 보인다.
V6 부터 스트로크는 `anchor(요소 id) + 정규화 좌표(x/폭, y/높이)` 로 저장한다.
화면이 바뀌어도 Q3 의 그림은 Q3 에 붙어 있고, 문서는 자유롭게 리플로우한다.
앵커가 사라진 스트로크는 **버리지 않고 보관하되 그리지 않는다** — 데이터 손실은 사용자 데이터 손상급이다.

## 8. 도메인 로버스트니스 — 구조는 공통, 증거는 과목별

6단계는 유지한다. 이건 편집 템플릿이 아니라 학습 사이클이다.
다만 **각 단계에 들어가는 학습행동까지 공통화하면 다시 취약해진다.**

| 단계 | 색보정 | 미분 | 이중슬릿 | 이벤트 소싱 |
|---|---|---|---|---|
| 관찰 | 실제 이미지 비교 | 표 + 그래프 변화 | 분포 변화와 장치 조건 | 상태 덮어쓰기 대 이벤트 스트림 |

"연습 5문제" 같은 공통 규격을 만들지 않는다.
**"이 목표를 증명하려면 어떤 증거가 필요한가"** 에서 수량이 나온다.

## 9. 출고 체크리스트 — 하나라도 '아니오' 면 출고 실패

| 검사 | 질문 | 강제 |
|---|---|---|
| 정확성 | 단순화가 절대법칙처럼 보이지 않는가? | 오개념 린트 · 검사관 |
| 경계조건 | 언제 안 되는지 최소 1개 보여주는가? | `boundary` 검증기 |
| 전이 | 본문과 다른 새로운 상황에서도 풀게 하는가? | far ≥ 2 · `전이 거리 허위` 린트 |
| 표상 다양성 | 텍스트 외 최소 2개 표상으로 설명하는가? | `표상 단일` 린트 |
| 오개념 복구 | 대표 오답별 피드백이 있는가? | `misconceptions` · `오해 방어 미이행` 린트 |
| 데이터 신뢰성 | first attempt 와 final answer 를 구분하는가? | `responses` 스키마 |
| 입력 대체수단 | 필기 없이도 응답할 수 있는가? | 렌더러가 `textarea` 를 낸다 |
| 환경 실패 | JS/슬라이더가 없어도 핵심학습이 가능한가? | 브라우저 테스트 |

## 10. 제품 원칙 (한 줄씩)

1. **Correct under simplification** — 쉽게 설명하되 틀리게 설명하지 않는다.
2. **Fail visibly** — 모형이 깨지는 조건을 숨기지 않는다.
3. **Measure learning, not completion** — "했다" 가 아니라 "무엇을 이해했는가" 를 기록한다.
4. **Multiple representations** — 하나의 설명 방식에 학습을 걸지 않는다.
5. **First-attempt matters** — 최종 정답보다 처음 사고와 수정 과정을 보존한다.
6. **Content before interaction** — 인터랙션이 없어져도 학습이 남아야 한다.
7. **Domain-specific evidence** — 과목마다 학습을 증명하는 방식이 달라야 한다.
8. **No false precision** — 교육용 모형에 근거 없는 숫자 정확도를 부여하지 않는다.
9. **Boundary cases are core content** — 예외는 부록이 아니라 개념의 일부다.
10. **Every abstraction states what it omits** — 모든 비유·모형은 무엇을 생략했는지 말한다.

## 11. 하나만 고른다면

> **"정상 케이스에서 잘 설명되는 학습지" 가 아니라
> "오해·예외·입력 실패·기기 차이·새로운 문제에서도 개념이 무너지지 않는 학습지" 를 만든다.**
