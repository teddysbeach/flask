### Q2. 디자인 시스템 — ✅ 해결

**결정: [Orca Design System](https://github.com/stablyai/orca) (MIT) 기반. 디자인은 마지막에 교체 가능.**

- Orca ADE 소스(`src/renderer/src/assets/main.css`)에서 실제 토큰 값을 추출해
  `design/design_tokens.json` 을 채웠다. Tailwind v4 + shadcn/ui 계열 중립 팔레트, Geist Variable, `--radius: 0.625rem`.
- Orca 가 자체 플러그인 패널에 노출하는 **20개 토큰 화이트리스트**를 불변 코어로 채택했다.
- 우리가 추가한 것: 브랜드 보라 액센트, 한글 폴백(Pretendard), 잉크 팔레트, 타이포 스케일, 학습지 문서 계층.
- **교체 지점은 `design/design_tokens.json` 하나.** 값만 바꾸고 재생성하면 앱과 학습지 HTML이 동시에 바뀐다.
  코드에는 색·간격·서체 리터럴이 존재하지 않는다(CI가 강제).

상세는 `02-design-system.md`.

**참고**: 원래 요구였던 `popol.me/designsystem` 은 이 작업 환경의 네트워크 정책에서 차단되어 값을 읽지 못했다.
나중에 값을 확보하면 위 교체 절차(`02-design-system.md` §3)로 4단계면 갈아끼워진다.

### Q4. 생성 모델 — ✅ 해결

**결정: 2단계 하이브리드. 설계 `claude-opus-5` → 집필 `claude-sonnet-5`. 장당 150원 이내.**

판단(무엇을·어떤 순서로·무엇이 사실인지)은 Opus 5가 작은 출력으로 끝내고,
토큰의 90%를 먹는 문장화는 Sonnet 5가 맡는다. 비싼 모델을 비싼 구간에만 쓴다.

| 단계 | 모델 | 출력 상한 | 비용 |
|---|---|---|---|
| ① 설계 | `claude-opus-5` | 1,000 tok | $0.0380 |
| ② 집필 | `claude-sonnet-5` | 6,000 tok | $0.0688 |
| **합계 (최악)** | | | **$0.1068 ≈ 149원** |

**두 가지 단서**
1. Opus 5의 thinking 토큰은 출력으로 과금되고 요청마다 양이 다르다.
   `max_tokens: 1000` 하드캡이 최후 방어선이고, **M2에서 30건 실측 후 `effort`와 캡을 확정한다.**
2. 150원은 환율(1,400원/USD)에 종속된다. 실제 관리는 **달러 기준** — 목표 `$0.105/장`, 경보 `$0.12/장`.

상세·대안 비교·런타임 가드는 `04-worksheet-spec.md` §4.

어느 쪽인지 알려주면 처리하겠다.

## B. 기술 리스크

| # | 리스크 | 영향 | 대응 |
|---|---|---|---|
| R1 | **WKWebView에서 Apple Pencil 필압이 안 나옴** | 필기 품질 = 제품 차별점 상실 | M0에서 최우선 spike. 실패 시 PencilKit 네이티브 플랫폼 뷰로 전환 (`06-annotation.md` §7) |
| R2 | **재렌더 시 DOM이 미세하게 달라져 필기가 어긋남** | 사용자 데이터 손상급 체감 | 렌더러를 순수 함수로 강제 + 골든 파일 테스트 + 고정 폭 문서 (`04` §6) |
| R3 | Edge Function 실행 시간 초과 | 생성 실패 | 비동기 잡 + `waitUntil` + 재시도. 그래도 초과하면 섹션 분할 생성으로 전환 |
| R4 | LLM 환각 (없는 인물/연도) | 학습 서비스의 신뢰 붕괴 | `confidence` 필드 + `uncertainty_note` + 프롬프트 정직성 규칙 + 회귀 테스트 (`04` §5) |
| R5 | **iOS 로컬 알림 64개 한도** | 복습 알림이 조용히 유실 | 롤링 재스케줄러(48개 상한) — 설계에 이미 반영 (`07` §4) |
| R6 | 알림 피로로 알림 끄기 | 리텐션 엔진 정지 | 일일 3개 상한 + 방해 금지 + 알림 문구를 문제 자체로 (가치 있는 알림) |
| R7 | LLM 비용 폭주 (어뷰징) | 금전 손실 | 쿼터 원자성 + 시간당 5회 레이트리밋 + 일일 지출 알람·소프트 차단 (`05` §5) |
| R8 | 필기 데이터 기기 간 충돌 | 필기 유실 | `rev` 낙관적 잠금 + 스트로크 단위 병합(append-only + tombstone) (`06` §5) |
| R9 | 프롬프트 인젝션 (`topic` 입력) | HTML 인젝션 / 프롬프트 탈취 | LLM은 JSON만 생성, HTML은 서버 렌더. 모든 문자열 이스케이프 (`04` §2) |
| R10 | 사용자가 부적절한 주제 입력 | 정책 위반 콘텐츠 | Claude의 `stop_reason: "refusal"` 을 감지해 `llm_refused` 로 처리, 쿼터 환불 |

## C. 의도적으로 나중에 미룬 결정

- 웹 버전 (Flutter Web) — 필기 UX가 데스크톱에서 의미가 달라짐. v2에서 재검토
- 학습지 공유 / 공개 링크 — 공유 시 필기를 포함할지가 별도 설계 이슈
- 필기 OCR / 자동 채점 — 정확도가 낮으면 안 하느니만 못함
- 학습지 편집 (사용자가 내용 수정) — 편집하면 필기 좌표가 깨진다. 하려면 버전 관리 필요
- 다국어 학습지
