# 18. 유저 플로우 버그 사냥 (1차)

기능 단위가 아니라 **사람이 앱을 쓰는 순서**대로 훑어 잡은 버그 열 개를 남긴다.
설치 → 약관 → 로그인 → 만들기 → 진행 → 학습지 → 복습 → 서재 → 결제 → 로그아웃.

여기 적는 이유는 자랑이 아니라 **재발을 막기 위해서**다. 열 개 중 여섯 개는
"각 조각의 테스트는 전부 초록인데 이어 붙이면 틀리는" 종류였다 — 그런 버그는
같은 자리에서 반드시 다시 난다. 그래서 하나마다 잣대(테스트)를 같이 박았다.

| # | 흐름 | 증상 | 원인 | 잣대 |
|---|---|---|---|---|
| 1 | 문의 | 로그인 못 하는 사람이 문의하기를 누르면 로그인 화면으로 튕긴다 | `Routes.publicPaths` 에 `/support/contact` 가 빠졌다. 서버 함수는 비로그인 접수를 허용하고 있었다 | `문의하기 로그인 없이 들어갈 수 있다` |
| 2 | 만들기 → 진행 | 학습지가 다 만들어져도 "학습지를 여는 중" 에서 안 빠져나온다 | 진행 화면을 `Navigator.push(MaterialPageRoute)` 로 라우터 **밖에** 얹어 두고, 완성 뒤 go_router 의 `pushReplacement` 를 불렀다 — 학습지가 진행 화면 아래에 깔린다 | `화면을 라우터 밖으로 얹는 코드가 없다` |
| 3 | 복습 | 3문제 중 1번을 풀면 2번이 아니라 3번이 나온다. 2번은 그날 영영 안 나온다 | 서버 큐를 그대로 보면서 `_index` 를 1 늘렸다. 답한 문제가 큐에서 빠지면 목록이 한 칸 당겨진다 | `답한 문제가 큐에서 빠져도 다음 문제를 건너뛰지 않는다` |
| 4 | 복습 | 하나도 못 떠올린 사람이 "오늘 5개를 떠올렸어요" 를 본다 | 등급과 무관하게 `_recalled += 1` | `"모르겠음" 은 떠올린 것으로 세지 않는다` |
| 5 | 복습(서버) | 같은 문제가 내일 두 번 나온다 | `answer-review` 가 state 를 읽고 나서 조건 없이 UPDATE 했다. 두 번 누르면 둘 다 통과해 relearn 이 두 줄 생긴다 | `답안 처리는 pending 인 줄만 집어간다` |
| 6 | 서재 | "실패" 필터를 걸면 다음 장에 더 있는데 1장만 보인다 | 필터는 화면 쪽인데 목록은 커서 페이징이다. 걸러진 목록이 화면을 못 채우면 스크롤이 안 생기고, 스크롤이 없으면 다음 요청도 없다 | `걸러진 목록이 화면을 못 채우면 스스로 다음 장을 불러온다` |
| 7 | 결제 | 앱 밖에서 끝난 결제(가족 승인·재전달)를 아무도 못 받는다 | 스트림을 구독하는 리포지터리를 **결제 화면만** 읽었다. 결제 화면을 안 열면 구독 자체가 없다 | `purchase_watcher.dart` (앱 껍데기가 들고 있다) |
| 8 | 로그아웃 | 로그아웃한 뒤에도 며칠 동안 잠금화면에 남의 학습지 제목이 뜬다 | 운영체제에 예약해 둔 알림은 앱 밖이라 로그아웃으로 안 지워진다. 앱 안 알림 기록도 남았다 | `기기에 남는 흔적 세 가지를 모두 지운다` |
| 9 | 약관 | 약관을 고쳐도 기존 사용자에게 다시 안 묻는다 | `ConsentRecord.version` 을 저장만 하고 판정은 `requiredAccepted` 만 봤다 | `약관이 바뀌면 로그인한 사람도 동의 화면으로 간다` |
| 10 | 관문 | 서버 설정 한 줄이면 앱이 아무 주소나 여는 도구가 된다 | `store_url` 을 검사 없이 `launchUrl` 로 넘겼다 | `스토어가 아닌 주소는 열지 않는다` |

## 남은 규칙

- **화면 이동은 전부 라우터를 거친다.** `MaterialPageRoute` 를 `lib/features` 에서 쓰면 테스트가 막는다(#2).
- **세션 중인 목록은 발밑에서 바꾸지 않는다.** 서버 큐를 다시 받는 것은 세션이 끝난 뒤다(#3).
- **확인하고 고치는 서버 코드는 조건부 UPDATE 로 쓴다.** 읽기와 쓰기 사이는 언제나 열려 있다(#5).
- **로그아웃은 세 곳을 지운다** — 오프라인 저장소, 예약된 알림, 알림 기록(#8).

# 앱 점검 2차 — 빠진 것 채우기

버그가 아니라 **없는 것**을 찾았다. 열넷 중 여섯은 "서버는 준비돼 있는데 앱에 부르는
곳이 없는" 종류였고, 넷은 화면에 아무 이상이 없어서 안 보이던 것이었다.

| # | 무엇이 없었나 | 왜 문제였나 | 어떻게 했나 |
|---|---|---|---|
| 1 | Pretendard 글꼴 파일 | 토큰이 이름으로 부르는데 저장소에 없어서 앱·학습지 모두 시스템 글꼴로 폴백 | `design/build_font.mjs` 로 KS X 1001 서브셋(2MB) 생성, 앱 번들에 넣고 WebView 는 `onpar-asset://` 로 같은 파일 사용 |
| 2 | 분석·크래시 어댑터 | 릴리스에서 아무것도 안 나가 크래시가 안 보이고 출시 지표를 잴 수 없었다 | 우리 서버로 보내는 텔레메트리(제3자 SDK 없음). 오프라인 큐·허용 목록·상한 |
| 3 | iOS 개인정보 매니페스트 | 앱 타깃의 것이 없으면 심사에서 걸린다 | `PrivacyInfo.xcprivacy` + Resources 빌드 단계 등록 |
| 4 | `/notices` 라우트 | 상수와 딥링크 파서는 있는데 라우터에 없어 "없는 페이지" 로 | 공지 테이블·화면·라우트. 로그인 없이 열린다 |
| 5 | 학습지 삭제 | RLS 는 허용하는데 UI 가 없어 계정 삭제만이 유일한 길이었다 | Edge Function(파일 먼저, 행 나중) + 뷰어 메뉴 |
| 6 | 제목 수정 | `grant update (title)` 이 있는데 부르는 곳이 없었다 | 뷰어 메뉴 |
| 7 | 인쇄·PDF | `@media print` CSS 는 있는데 부를 버튼이 없었다 | 뷰어 메뉴에서 `printCurrentPage()` |
| 8 | 재부팅 뒤 알림 복원 | 폰을 껐다 켜면 예약이 전부 사라졌다 | `RECEIVE_BOOT_COMPLETED` + 부팅 리시버 |
| 9 | 고아 파일 감시 | 생성이 끊기면 Storage 에 파일만 남았다 | `storage_orphans` 뷰(보여만 준다) |
| 10 | 무료 장수 남용 통제 | 계정을 새로 만들면 또 2장 | 하루 생성 상한(30장). 실패한 생성은 안 센다 |
| 11 | 한국어 Material | "Cut / Copy / Paste" 가 영어로 떴다 | `flutter_localizations` |
| 12 | 학습 기록 | 데이터는 쌓이는데 보여주지 않아 리텐션 장치가 알림뿐이었다 | `learning_stats()` + 기록 화면(연속일·떠올린 비율) |
| 13 | 서재 검색 | 50장을 넘기면 못 찾는다 | 받아 온 것 안에서 검색 + 못 찾으면 더 불러오기 |
| 14 | 데이터 내보내기 | 지우는 길만 있고 가져가는 길이 없었다 | 계정 화면에서 JSON 내보내기(이동권) |

## 남은 규칙

- **글꼴은 앱이 한 벌만 들고 먹인다.** 학습지에 구우면 한 장에 200KB 가 붙어
  오프라인 보관과 스토리지가 같이 세 배가 된다.
- **텔레메트리는 허용 목록으로 거른다.** 막을 키를 나열하면 새 화면이 새 키를 만들 때 뚫린다.
- **삭제는 파일 먼저, 행은 나중.** 행을 먼저 지우면 경로를 잃어 파일을 영영 못 찾는다.
- **연속 학습일은 어제까지 이어졌으면 살아 있다.** 하루 늦게 연 사람의 노력을 0 으로
  만들면 다시 시작할 마음까지 사라진다.

# 동작하지 않던 버튼 추적

"코드는 멀쩡하고 테스트도 통과하는데 아무도 그리로 갈 수 없는" 종류를 훑었다.
이 저장소에서만 다섯 번 났다.

| 무엇 | 어떻게 죽어 있었나 | 어떻게 했나 |
|---|---|---|
| Google 로그인 | `Env.googleIosClientId` 가 **이미 있는데** 화면이 `null` 을 넘기고 있었다. iOS 의 google_sign_in 은 클라이언트 ID 없이는 시작조차 못 하므로 눌러도 아무 일이 안 났다 | 값을 넘기고, **값이 없는 빌드에서는 버튼을 감춘다**(Apple 로그인을 안드로이드에서 감추는 것과 같은 규칙) |
| 내 문의 | RLS `support_tickets_select_own` 도 있고 접수 번호도 주는데 **볼 화면이 없었다.** 게다가 답을 담을 컬럼조차 없어서 "답변됨" 이 빈말이었다 | `answer`·`answered_at` 컬럼 + 운영용 함수 + 문의함 화면. 고객센터와 접수 완료 화면에서 들어간다 |
| 공지 `/notices` | 상수와 딥링크 파서는 만들어 내는데 라우터에 등록이 없었다 | (앞 절) 화면·라우트 |
| 알림함 `/notifications` | 라우트만 있고 누르는 곳이 하나도 없었다 | 홈 앱바에 안 읽음 점과 함께 |
| "서재로 가기" 버튼들 | 홈이 모든 학습지를 갖게 된 뒤로 **라벨이 거짓말**이 됐다(찾기 탭에는 검색이 있을 뿐) | 홈으로 보낸다 |

## 이 종류를 잡는 잣대

`app/test/reachability_test.dart` 가 세 가지를 값으로 잰다.

1. **라우터에 등록된 화면에 들어갈 길이 있는가** — 리다이렉트·탭이 맡는 것만 예외로 둔다.
2. **빈 콜백이 없는가** — `onPressed: () {}` 는 자리만 잡고 사용자를 속인다.
3. **화면에 TODO 가 남아 있지 않은가** — 화면의 TODO 는 대개 "이 버튼은 아직 안 된다" 는 뜻이다.

셋 다 일부러 어겨 보고 빨개지는 것을 확인했다.
