# 19. 모션

무엇이 어떻게 움직이는가. 값은 `design/design_tokens.json` 의 `motion` 이 원본이고,
앱(`tokens.g.dart`)과 학습지(`tokens.css.ts`)가 **같은 값**을 받아 쓴다.

---

## 1. 기준은 애플이다

취향이 아니라 이 앱이 사는 곳 때문이다. 아이패드에서 애플펜슬로 쓰는 앱이라
화면의 움직임이 iOS 와 다르면 "이 앱만 느리다 / 이 앱만 튄다" 로 읽힌다.
애플에서 가져온 것은 둘이다.

1. **거의 모든 전환이 감속이다.** 빠르게 출발해 천천히 놓는다.
2. **사라지는 것은 나타나는 것보다 빠르다.** 기다림은 등장에만 쓴다.

곡선은 요즘 쓰는 값으로 골랐다. quint·expo 계열은 끝에서 길게 눕는 곡선이라
짧은 시간에도 "천천히 놓았다" 는 인상이 남는다 — 애플의 스프링이 주는 인상과 같다.

## 2. 곡선

| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| `standard` | `cubic-bezier(0.32, 0.72, 0, 1)` | 화면 전환·시트·상태 색. iOS 시트가 올라올 때의 곡선 |
| `enter` | `cubic-bezier(0.22, 1, 0.36, 1)` | 들어오는 것 (easeOutQuint) — 목록·카드·본문 |
| `exit` | `cubic-bezier(0.4, 0, 1, 1)` | 나가는 것 (easeIn) |
| `emphasized` | `cubic-bezier(0.16, 1, 0.3, 1)` | 강조 등장 (easeOutExpo) — **화면당 한 번** |
| `spring` | `cubic-bezier(0.34, 1.4, 0.64, 1)` | 끝에서 살짝 넘긴다. 축하·완료·눌림 복귀에만 |

`spring` 은 1 을 넘겼다 돌아오므로 **색 보간에는 쓰지 않는다**(범위를 벗어난다).
테스트가 이 다섯 곡선의 성질을 잰다 — `app/test/motion_test.dart`.

## 3. 시간

`instant 90` · `fast 160` · `base 240` · `slow 360` · `slower 520` (ms).
짧을수록 자주 쓰는 것이다. 자주 보는 움직임이 길면 앱 전체가 느려 보인다.
목록 시차는 `stagger 40ms`, 등장 이동 거리는 `travel 12dp`, 눌림은 `pressScale 0.97`.

## 4. 어디에 얹었나 — 화면마다가 아니라 **한 곳씩**

29개 화면에 각각 애니메이션을 적으면 반드시 어긋난다. 그래서 공용 지점에 얹었다.

| 지점 | 덮는 범위 |
|---|---|
| `dsThemeData` 의 `pageTransitionsTheme` | **모든 화면의 전환**(밀려 들어오기 + 이전 화면 시차) |
| `HomeShell` 의 크로스 페이드 | 탭 네 개 사이 — 좌우로 밀지 않는다(탭은 앞뒤가 아니라 나란히 있다) |
| `FormScaffold` | 로그인·가입·인증·비밀번호·프로필·탈퇴·문의 등 폼 화면 전부 |
| `SettingsSection` | 설정·계정·고객센터의 목록 묶음 |
| `EmptyView` · `ErrorView` · `OfflineBanner` | 모든 화면의 빈 상태·오류·오프라인 |
| `dsAsync(...)` | 로딩 → 내용 전환(홈·서재·복습·결제·알림·학습지·진행) |
| `DsPressable` | 카드·타일·보기·버튼의 눌림 |

화면 고유의 순간에만 따로 얹었다 — 스플래시 로고, 온보딩, 관문, 만드는 중 단계,
복습 카드 교체와 답 열림, 완료 요약(여기만 `spring`), 탈퇴 3단계, 결제 시트.

## 5. 학습지에만 있는 제약: 필기

**이 문서의 모션 규칙 중 다른 어디에도 없는 것.**

획은 `[data-ink-anchor]` 요소(`.ink-space`)의 사각형에 정규화되어 저장된다.
`getBoundingClientRect` 는 transform 을 반영하므로, 필기 칸을 품은 조상에
**움직이는** transform 이 걸리면 애니메이션이 도는 동안 그린 획이 어긋난 자리에
저장된다. 그래서:

1. `transform` 은 **컨트롤에만** — summary·button. 이들은 `.ink-space` 를 품지 않는다.
2. 본문 블록은 **opacity 만**. 밝기는 사각형을 건드리지 않는다.
3. 자리(레이아웃)는 언제나 즉시 열린다. 답이 열릴 때 글자만 천천히 밝아진다.

고정 transform 은 괜찮다 — `.sheet-scaler` 의 배율이 그것이고 필기 런타임이
그 배율을 알고 나눠 쓴다. 문제는 **시간에 따라 변하는** transform 뿐이다.
Chromium 테스트가 이것을 실제로 잰다(`server/tests/interact.browser.test.ts`).

## 6. 동작 줄이기는 예외가 없다

OS 에서 켜 두었으면 취향이 아니라 요청이다.

* 앱: `dsDuration(context, …)` 이 0 을 돌려주고, `DsFadeSlide` 는 끝난 상태로 그린다.
  **내용을 숨기지 않는다** — 움직임을 줄여 달라는 요청이지 빼 달라는 요청이 아니다.
* 학습지: `@media (prefers-reduced-motion: reduce)` 가 전환·애니메이션을 0.01ms 로 만든다.
* 페이드는 `alwaysIncludeSemantics: true` 로 둔다. 투명한 동안에도 스크린리더가 읽는다.

두 쪽 모두 테스트가 지킨다 — 앱은 `motion_test.dart`, 학습지는 브라우저 테스트가
"동작 줄이기를 켰는데 전환이 남아 있는지" 를 실제로 잰다.
