# 09. 미결정 사항 & 리스크

## A. 답이 필요한 질문 (착수 전)

### Q1. 앱 이름
계획서는 코드네임 **Baewoom(배움)** 으로 진행한다. 정식 명칭이 있으면 알려달라.
패키지 ID(`me.popol.baewoom` 등)와 스토어 등록에 필요하다.

### Q2. popol.me 디자인 토큰 ⛔ **최우선 블로커**
`https://popol.me/designsystem` 이 이 작업 환경의 네트워크 정책에서 **차단**되어 실제 값을 읽지 못했다.
(도메인 차단이며 일시적 오류가 아니다. 우회하지 않고 그대로 보고한다.)

전달 방법 중 하나를 선택해 달라:
1. 토큰 표를 그대로 붙여넣기 (색상 hex, 서체, 스케일, 라운딩, 그림자)
2. Figma Variables / Tokens Studio JSON export
3. 사이트 접근이 가능한 환경에서 `design/design_tokens.json` 을 채워 커밋

추출해야 할 항목 전체는 `02-design-system.md` §3 체크리스트에 있다.
**토큰 없이는 UI 구현을 시작하지 않는다** — 임시 색상을 깔면 나중에 전수 치환이 불가능해지고
"반드시 popol.me 디자인을 따를 것"이라는 요구를 위반한다.

### Q3. 무료 2장을 다 쓰면?
계획서는 "곧 제공" 화면으로 막아뒀다(결제 v1 제외). 선택지:
- (a) v1 그대로 막는다 — 대기자 명단만 수집
- (b) 인앱구매(소모성 아이템: 학습지 5장 묶음)를 v1에 넣는다
- (c) 친구 초대 시 +1장

### Q4. 생성 모델 선택
기본값 `claude-opus-5` (1장 ≈ $0.23). 무료 2장 = 사용자당 ≈ $0.46.
품질을 우선한 선택이지만 예산에 따라 조정 가능하다:
- (a) 전부 Opus 5 — **권장.** 무료 2장이 곧 전환율
- (b) 전부 Sonnet 5 — 1장 ≈ $0.10. 탄생 배경·상황극 섹션의 깊이가 눈에 띄게 얕아질 위험
- (c) 하이브리드 — 본론/탄생배경/상황극은 Opus 5, 사전학습 제안·다음 단계 목록만 Haiku 4.5.
      호출이 2번으로 늘어 복잡도가 오르지만 30% 정도 절감

월 예산 상한을 알려주면 (a)/(c) 중에 정하겠다.

v1은 한국어 전용으로 잡았다. 영어 주제 입력도 한국어 학습지로 나온다. 맞나?

### Q7. 기존 `langhelper/` Flask 코드 — ✅ 해결

**결정: 전부 삭제.** 백지에서 새로 시작한다. (2026-09-06 적용 완료)

- `langhelper/` 24개 파일 삭제 (`site.db`, `__pycache__` 포함)
- `.gitignore` 를 신규 스택(Flutter · Supabase · Deno) 기준으로 교체

**남은 한 가지**: 삭제해도 **git 히스토리에는 여전히 남아 있다.**
`langhelper/app/site.db` 에 실제 사용자 계정·일기 데이터가 들어 있었다면
히스토리 재작성(`git filter-repo`)이 필요하다. 테스트 데이터뿐이면 그냥 둬도 된다.
어느 쪽인지 알려주면 처리하겠다.

## B. 기술 리스크

| # | 리스크 | 영향 | 대응 |
|---|---|---|---|
| R1 | **WKWebView에서 Apple Pencil 필압이 안 나옴** | 필기 품질 = 제품 차별점 상실 | M0에서 최우선 spike. 실패 시 PencilKit 네이티브 플랫폼 뷰로 전환 (`06-annotation.md` §7) |
| R2 | **재렌더 시 DOM이 미세하게 달라져 필기가 어긋남** | 사용자 데이터 손상급 체감 | 렌더러를 순수 함수로 강제 + 골든 파일 테스트 + 고정 폭 문서 (`04` §6) |
| R3 | Edge Function 실행 시간 초과 | 생성 실패 | 비동기 잡 + `waitUntil` + 재시도. 그래도 초과하면 섹션 분할 생성으로 전환 |
| R4 | LLM 환각 (없는 인물/연도) | 학습 서비스의 신뢰 붕괴 | `confidence` 필드 + `uncertainty_note` + 프롬프트 정직성 규칙 + 회귀 테스트 (`04` §5) |
| R5 | **iOS 로컬 알림 64개 한도** | 복습 알림이 조용히 유실 | 롤링 재스케줄러(48개 상한) — 설계에 이미 반영 (`07` §4) |
| R6 | 알림 피로로 알림 끄기 | 리텐션 엔진 정지 | 일일 3개 상한 + 방해 금지 + 알림 문구를 문제 자체로 (가치 있는 알림) |
| R7 | LLM 비용 폭주 (어뷰징) | 금전 손실 | 쿼터 원자성 + 시간당 5회 레이트리밋 + 일일 지출 알람·소프트 차단 (`05` §5) |
| R8 | 필기 데이터 기기 간 충돌 | 필기 유실 | `rev` 낙관적 잠금 + 스트로크 단위 병합(append-only + tombstone) (`06` §5) |
| R9 | 프롬프트 인젝션 (`topic` 입력) | HTML 인젝션 / 프롬프트 탈취 | LLM은 JSON만 생성, HTML은 서버 렌더. 모든 문자열 이스케이프 (`04` §2) |
| R10 | 사용자가 부적절한 주제 입력 | 정책 위반 콘텐츠 | Claude의 `stop_reason: "refusal"` 을 감지해 `llm_refused` 로 처리, 쿼터 환불 |

## C. 의도적으로 나중에 미룬 결정

- 웹 버전 (Flutter Web) — 필기 UX가 데스크톱에서 의미가 달라짐. v2에서 재검토
- 학습지 공유 / 공개 링크 — 공유 시 필기를 포함할지가 별도 설계 이슈
- 필기 OCR / 자동 채점 — 정확도가 낮으면 안 하느니만 못함
- 학습지 편집 (사용자가 내용 수정) — 편집하면 필기 좌표가 깨진다. 하려면 버전 관리 필요
- 다국어 학습지
